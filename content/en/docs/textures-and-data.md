# Textures and Data

## Goal

Use `sampler2D` and `samplerCube` correctly, reason about UV wrapping and
mip levels, build a tangent frame for normal mapping, and add your own uniforms
and textures without editing declarations by hand.

## Sampling a 2D texture

A sampler is a handle; `texture()` returns a `vec4`:

```glsl
uniform sampler2D albedoTexture;

vec4 texel = texture(albedoTexture, vUv);
vec3 rgb = texel.rgb;
```

`texture` chooses a mip level automatically from the screen-space derivatives of
the UV. That is correct for surface shading. Use `textureLod` when you need a
specific level (blur chains, roughness lookups) and `texelFetch` when you need an
integer texel without filtering.

## UV wrapping

Wrapping is a sampler-state property, not a GLSL property:

- **Repeat** — UVs outside `[0, 1]` tile.
- **Clamp** — UVs outside `[0, 1]` stretch the edge.
- **Mirror** — UVs outside `[0, 1]` flip.

If a texture looks like it is smearing at the edges, the sampler is clamped. If
it repeats when you expected a single image, the sampler is repeating. The
texture picker uses the preview's default; you cannot change wrapping from the
shader.

## Normal mapping

A normal map stores a direction in tangent space. To use it you need a
per-vertex tangent frame:

```glsl
vec3 N = normalize(vWorldNormal);
vec3 T = normalize(vWorldTangent - N * dot(N, vWorldTangent));
vec3 B = cross(N, T);

vec3 tangentNormal = texture(normalTexture, vUv).rgb * 2.0 - 1.0;
vec3 worldNormal = normalize(T * tangentNormal.x + B * tangentNormal.y + N * tangentNormal.z);
```

Why the Gram–Schmidt step? The interpolated tangent and normal are not perfectly
perpendicular. Removing the normal component of the tangent keeps the frame
orthonormal; otherwise the normal map is skewed.

The `normal-map` example avoids a texture and differentiates a procedural height
field instead, but the frame construction is identical.

## Cube maps

A `samplerCube` is sampled with a direction, not a UV:

```glsl
uniform samplerCube environmentMap;

vec3 reflected = reflect(-viewDirection, normal);
vec3 environment = texture(environmentMap, reflected).rgb;
```

The preview binds `environmentMap`, `irradianceMap`, `prefilteredEnvironmentMap`
and `brdfLUT`. The last three are the ingredients of the IBL lesson:
`irradianceMap` for diffuse, `prefilteredEnvironmentMap` for specular, and
`brdfLUT` for the split-sum approximation.

## User data

The User data tab is how you add a uniform or texture without editing the
declarations into the shader:

1. Add a row and choose a name and kind.
2. Choose the stages that receive the generated declaration (`Frag`, `Vert`,
   `All`, or `Post`).
3. Set a value. Value edits bind live; structural edits rebuild the shader.

The generated block is read-only in the editor and is injected above the
injection point. A shader that references `albedo` must **not** declare
`uniform vec3 albedo;` itself — the block already does, and the duplicate
declaration fails to compile.

Texture rows use `sampler2D` or `samplerCube`. The 2D Sandbox offers only
`sampler2D`; the screen-space editor offers only post-stage definitions.

```glsl
// Generated by User data:
// uniform vec3 albedo;
// uniform float roughness;
// uniform sampler2D detailMap;

vec4 detail = texture(detailMap, vUv * 4.0);
vec3 color = albedo * detail.rgb;
```

## Minimal example: a procedural normal map

```glsl run=editor example=normal-map title="Normal-map example"
#version 300 es
precision highp float;

in vec3 vWorldPosition;
in vec3 vWorldNormal;
in vec3 vWorldTangent;
in vec2 vUv;

uniform vec3 cameraPos;
uniform vec3 lightDir;

out vec4 fragColor;

void main(void)
{
    vec3 N = normalize(vWorldNormal);
    vec3 T = normalize(vWorldTangent - N * dot(N, vWorldTangent));
    vec3 B = cross(N, T);

    float frequency = 36.0;
    float dx = cos(vUv.x * frequency) * sin(vUv.y * frequency);
    float dy = sin(vUv.x * frequency) * cos(vUv.y * frequency);

    vec3 perturbed = normalize(N - normalStrength * (dx * T + dy * B));

    float NdotL = max(dot(perturbed, normalize(lightDir)), 0.0);
    fragColor = vec4(albedo * (0.12 + 0.88 * NdotL), 1.0);
}
```

## Exercises

1. Change the normal-map frequency from `36.0` to `8.0`. What happens to the
   apparent surface roughness?
2. Set `normalStrength` to `0.0`. Does the surface become flat or just lose the
   perturbation?
3. Multiply the UV by `4.0` when sampling the texture. What changes, and which
   sampler state would make it tile?
4. In the reflections example, change `reflect(-viewDirection, normal)` to
   `reflect(viewDirection, normal)`. What happens to the reflection?
5. Add a `sampler2D` row in User data and sample it. Which stage must it target
   to be visible in the fragment shader?

::: solution Solution 1
Lower frequency means larger, smoother bumps. The normal perturbation changes
more slowly across the surface, so the highlights get broader.
:::

::: solution Solution 2
The perturbed normal becomes the geometric normal; the surface is lit as if it
had no normal map, but the underlying geometry is unchanged.
:::

::: solution Solution 3
The texture repeats four times across the UV range. That only works if the
sampler wraps with **repeat**; with clamp, the edge pixels stretch instead.
:::

::: solution Solution 4
The reflected direction points into the surface, so the cubemap lookup returns
the environment behind the object. The reflection appears inverted.
:::

::: solution Solution 5
`Frag` (or `All`). A `Vert`-only declaration is not visible in the fragment
shader, and a `Post` declaration only reaches effect passes.
:::

## Common mistakes

- Declaring a uniform that User data already generates.
- Forgetting to decode a normal map (`rgb * 2.0 - 1.0`).
- Using the vertex `normal` as the normal-map basis without a tangent.
- Sampling a cubemap with a UV instead of a direction.
- Expecting `texture()` to wrap when the sampler is clamped.
